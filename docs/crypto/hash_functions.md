# Vellum: Algebraic Hash Functions and In-Circuit Primitives

Traditional cryptographic hash functions such as SHA-256 and Keccak-256 are optimized for hardware logic and 32/64-bit boolean microarchitectures (bitwise rotations, shifts, and XORs). In an arithmetic circuit over a large prime field, decomposing words into bits and computing boolean relations requires tens of thousands of constraints per hash invocation.

Vellum provides in-circuit native algebraic hash functions designed specifically for finite field arithmetic, reducing constraint overhead by two orders of magnitude.

---

## 1. The Poseidon Hash Function

Poseidon is an algebraic hash function operating directly over prime fields $\mathbb{F}_p$. It is structured around the **Hades** permutation strategy, combining full S-box rounds with partial S-box rounds to maximize algebraic diffusion while minimizing non-linear constraints.

### 1.1 State and Parameters
- **State Width ($t$)**: State size in field elements (e.g., $t = 3$ for 2-to-1 hashing).
- **S-box**: Power map $S(x) = x^5$ (chosen because $\gcd(5, p - 1) = 1$ in BN254).
- **Rounds**: $R_F$ full rounds at the beginning and end; $R_P$ partial rounds in the middle.
  - Full rounds apply $S(x)$ to all $t$ state elements.
  - Partial rounds apply $S(x)$ only to the last state element $s_{t-1}$, leaving the other $t-1$ elements to be mixed linearly.

### 1.2 Round Structure
Each round consists of three transformations:
1. **AddRoundConstant ($ARC$)**: Pointwise addition of pseudo-random round constants $C_i$ generated by a Grain LFSR:
   $$s_j \leftarrow s_j + C_{i, j}$$
2. **SubWords ($SB$)**: Non-linear monomial substitution:
   - Full round: $s_j \leftarrow s_j^5$ for all $0 \le j < t$
   - Partial round: $s_{t-1} \leftarrow s_{t-1}^5$, $s_j \leftarrow s_j$ for $j < t - 1$
3. **MixLayer ($M$)**: Vector-matrix multiplication with a Maximum Distance Separable (MDS) Cauchy or circulant matrix $M$:
   $$s \leftarrow M \cdot s$$

In an R1CS circuit, computing $x^5$ requires only 3 multiplications ($x^2 = x \cdot x$, $x^4 = x^2 \cdot x^2$, $x^5 = x^4 \cdot x$), making a 2-to-1 Poseidon compression cost only approx. 240 constraints, compared to ~25,000 constraints for SHA-256.

## 2. The Rescue Hash Function

Rescue is an algebraic permutation based on a symmetric Substitution-Permutation Network (SPN). Unlike Poseidon, every round of Rescue applies both a forward S-box $x^\alpha$ and an inverse S-box $x^{1/\alpha}$.

### 2.1 Round Pipeline
1. Forward non-linear step: $s \leftarrow s^\alpha$
2. Linear step: $s \leftarrow M \cdot s + K_{2r}$
3. Inverse non-linear step: $s \leftarrow s^{1/\alpha}$
4. Linear step: $s \leftarrow M \cdot s + K_{2r+1}$

The alternating power maps ensure high algebraic degree in both forward and backward directions, offering provable resistance against Gröbner basis algebraic cryptanalysis.

## 3. GMiMC (Generalized Feistel Permutation)

GMiMC utilizes an unbalanced Generalized Feistel scheme. In GMiMC-Erf, each round updates a single branch using a power map $x^3$ or $x^5$:
$$s_0' = s_0 + s_1^3 + C_i$$
$$s_j' = s_{j+1} \quad (j > 0)$$
This structure requires only one non-linear operation per round, resulting in compact circuit representations for wide state arrays.

## 4. RFC 7693 BLAKE2s

For verification outside circuits or when interfacing with external data structures, Vellum includes a pure Ruby implementation of BLAKE2s (RFC 7693).

### Architectural Highlights
- 32-bit word arithmetic with 8-word internal state and 16-word message schedule.
- $G$ function mixing quarter-states via modular additions, rotations, and XORs:
  $$a \leftarrow a + b + m_{\sigma_r[2i]}$$
  $$d \leftarrow (d \oplus a) \ggg 16$$
  $$c \leftarrow c + d$$
  $$b \leftarrow (b \oplus c) \ggg 12$$
  $$a \leftarrow a + b + m_{\sigma_r[2i+1]}$$
  $$d \leftarrow (d \oplus a) \ggg 8$$
  $$c \leftarrow c + d$$
  $$b \leftarrow (b \oplus c) \ggg 7$$
- Verified bit-for-bit against official cryptographic test vectors and standard implementations across all standard block and key configurations.
